# 서천군청 정책관리 ERP 시스템 — 목표문서 (요구사항 정의서)

> **문서 성격**: 시스템 구축에 앞서 도입 목표와 요구사항을 정리한 종합 기획·요구사항 문서
> **대상 조직**: 충청남도 서천군청
> **작성일**: 2026-05-30
> **버전**: v0.1 (초안)

---

## 1. 문서 개요

### 1.1 목적
본 문서는 서천군청 각 부서 기획팀이 시행 중·구상 중인 정책을 한곳에 모아 공유·논의하고,
주요업무 보고회와 순기표를 체계적으로 관리하며, 데이터 기반의 정책 판단을 지원하는
**내부 정책관리 ERP 시스템**의 도입 목표와 요구사항을 정의한다. 이해관계자 공유·보고와
향후 개발 착수의 기준 자료로 동시에 활용한다.

### 1.2 대상 독자
- 의사결정자(부군수·기획감사실 등 승인 라인)
- 시스템 도입 담당자(관리자)
- 실제 사용 부서(각 부서 기획팀, 부서 서무)
- 개발/구축 담당자(외주 또는 내부)

### 1.3 용어 정의
| 용어 | 정의 |
|------|------|
| 정책(시행정책) | 현재 서천군에서 시행되고 있는 정책 |
| 정책(구상정책) | 아직 시행 전, 구상·검토 중인 정책 아이디어 |
| 유형화(분류) | 정책·사업을 분야/성격에 따라 카테고리로 구분하는 것 |
| 분야 | 정책이 속하는 행정 분야(예: 복지, 농업, 관광, 환경 등) |
| 주요업무 보고회 | 연 3회(2·7·11월) 개최, 부서별 주요사업을 보고·관리하는 회의 |
| 순기표 | 분기 1회(1·4·7·10월) 작성, 서천군의 **모든 사업**을 관리하는 표 |
| 정책적 주요사업 | 순기표 사업 중 정책적으로 중요하다고 판단되어 별도 관리하는 사업 |
| 서무 | 각 부서에서 주요업무·순기표 입력을 담당하는 직원 |
| 읍면 | 서천군 내 행정구역 단위(지역별 분석 기준) |

## 2. 추진 배경 및 목표

### 2.1 현황 및 문제점
- 각 부서의 시행·구상 정책 정보가 부서별로 흩어져 있어 **전체 현황 파악이 어렵다.**
- 정책에 대한 의견을 자유롭게 모으고 검토할 **상시 협업 채널이 부재**하다.
- 주요업무 보고회·순기표 자료를 **수기(한글/엑셀)로 취합**하여 시간이 많이 들고,
  회차 간 변경 내역·진행 추적이 어렵다.
- 사업비·지역별 분포 등 **데이터 기반의 정책 판단 근거**가 부족하다.

### 2.2 도입 목표
1. **정책 통합 관리**: 시행·구상 정책을 한 시스템에 모아 유형/분야별로 분류·검색.
2. **상시 협업·의견 수렴**: 정책별 자유 의견과 분야별 사업 제안으로 집단지성 활용.
3. **보고 업무 디지털화**: 주요업무 보고회·순기표를 표준 양식으로 입력·관리하고
   회차/분기 간 변경을 자동 추적.
4. **데이터 기반 의사결정**: 유형별·지역(읍면)별 사업비 등 지표를 대시보드로 시각화하여
   "무엇이 군에 필요하고, 무엇이 잘되고 있는지" 판단 근거 제공.
5. **권한 기반 운영**: 로그인·권한 체계로 정보 보안과 업무 책임을 명확화.

### 2.3 기대효과
| 구분 | 기대효과 |
|------|----------|
| 정성적 | 정책 정보 가시성 향상, 부서 간 협업·아이디어 공유 활성화, 보고 자료 표준화 |
| 정량적 | 보고회·순기표 취합 시간 단축, 자료 재작성/중복 입력 감소, 변경 추적 누락 방지 |

## 4. 기능 요구사항

### 4.1 정책 아카이브 (시행 중 / 구상 중 정책)
- 정책 등록 시 **상태 구분**: `시행정책` / `구상정책`.
- 입력 항목(예): 정책명, 상태, **유형(분류) 선택**, 분야, 담당 부서·팀, 작성자, 요약,
  상세 내용, 관련 사업비(선택), 기간(선택), 첨부자료.
- **분류·검색·필터**: 시행정책과 구상정책을 각각 유형/분야/부서/기간으로 분류해 열람.
  키워드 검색, 다중 필터, 목록/카드 보기 지원.
- 구상정책이 시행으로 전환될 때 상태 변경 및 이력 기록.

### 4.2 의견 · 아이디어 (협업)
- **정책별 자유 의견**: 각 정책에 댓글 형태로 의견을 자유롭게 작성.
- **분야별 사업 제안**: "어떤 분야에 어떤 사업을 하면 좋을지" 제안하는 게시판.
  제안 시 분야/유형 선택, 기대효과·근거 작성.
- **추천/공감**: 의견·제안에 추천을 표시하여 군에 도움이 될 정책을 식별.
- 작성자/부서 표시, 정렬(최신/추천순), 분야별 모아보기.

### 4.3 주요업무 보고회 관리 (연 3회: 2월 · 7월 · 11월)
부서 **서무**가 정해진 양식으로 사업을 입력·관리한다.

**입력 항목**
| # | 항목 | 비고 |
|---|------|------|
| 1 | 부서명 | 공통코드 |
| 2 | 팀명 | 공통코드 |
| 3 | 사업명 | |
| 4 | 목표 및 방향성 | |
| 5 | 사업비 | 금액(원/천원), 분석 대상 |
| 6 | 사업기간 | 시작~종료 |
| 7 | 사업위치 | 읍면 연계 권장 |
| 8 | 사업내용 | |
| 9 | 추진현황 | 진행 상태/진행률 |
| 10 | 향후계획 | 다음 회차 추적 기준 |
| 11 | 문제점 및 해결방안 | |
| 12 | 기대효과 | |
| 13 | 참고자료 | **위치도·현장사진 등 이미지 첨부** |

**회차별 변경 추적**
- 보고회 회차(예: 2026-02, 2026-07, 2026-11)별 데이터를 **스냅샷**으로 보존.
- 직전 회차의 **향후계획** 대비 다음 회차의 실제 **추진현황**을 비교 표시하여,
  "향후계획대로 진행되지 않거나 변경된 내용"을 한눈에 파악.
- 변경 이력(누가/언제/무엇을) 기록.

### 4.4 순기표 관리 (분기: 1월 · 4월 · 7월 · 10월)
- 주요업무 보고회와 유사한 양식이되, **주요사업뿐 아니라 서천군의 모든 사업**을 관리.
- 분기 회차(예: 2026-Q1=1월 …)별로 입력·보존, 향후계획 대비 진행 변경 추적(4.3과 동일 구조).
- **정책적 주요사업 지정**: 사업별로 "정책적으로 주요하다"고 판단되는 사업을 **체크**.
  체크된 사업은 **별도 관리 화면**에서 다음 기준으로 관리·집계:
  - **부서별**
  - **읍면별**
  - **기간별(종료연도 기준)**

### 4.5 첨부 / 이미지 자료 관리
- 위치도, 현장 사진 등 **이미지 업로드·미리보기**.
- 허용 형식(jpg/png/pdf 등)·용량 제한 정책 정의, 항목(정책/주요업무/순기표)별 첨부 연결.

## 5. 데이터 모델 개요

### 5.1 핵심 엔터티 및 관계
```
사용자(User) ── 소속 ──> 부서(Dept) ── 팀(Team)
정책(Policy) ── 분류 ──> 유형(Type), 분야(Field)
정책(Policy) ──< 의견(Comment) / 사업제안(Idea)
주요업무(MajorTask) ──< 회차스냅샷(ReportSnapshot: 2·7·11월)
순기표(CycleItem) ──< 분기스냅샷(QuarterSnapshot: 1·4·7·10월)
순기표(CycleItem) ── 주요사업체크(flag) ── 읍면(Town), 종료연도(EndYear)
모든 사업·정책 ──< 첨부파일(Attachment: 이미지/문서)
공통코드(Code): 부서·팀·읍면·유형·분야·상태
```

### 5.2 공통코드 관리
부서, 팀, 읍면, 유형(분류), 분야, 상태값을 **공통코드**로 일원화하여 관리자가
화면에서 추가/수정/비활성화. 조직 개편·분류 체계 변경에 유연하게 대응.

## 6. 대시보드 / 분석

### 6.1 주요 지표
- **유형(분류)별 사업비** 합계·비중
- **지역(읍면)별 사업비** 합계·비중
- 부서별 사업 수·사업비
- **종료연도별** 사업 분포(순기표 주요사업 기준)
- 추진현황(진행률) 분포, 정책적 주요사업 비중

### 6.2 시각화 및 활용
- 막대/파이/표, 가능 시 지도(읍면) 시각화.
- 필터: 기간(회차/분기/연도), 부서, 읍면, 유형, 분야, 상태.
- 활용 시나리오: "어느 분야·지역에 사업비가 집중/부족한지", "잘 진행되는 사업 vs 지연 사업"을
  비교해 정책 우선순위 판단 근거로 사용.

## 7. 비기능 요구사항
- **보안/접근통제**: 군청 내부망 운영 전제, 로그인·세션 관리, 권한 기반 접근통제(RBAC).
- **이력/감사 로그**: 주요 데이터의 생성·수정·삭제 및 회차/분기 변경 이력 기록.
- **백업/복구**: 정기 백업 및 복구 절차.
- **사용성**: 20명 규모에 맞는 단순·직관적 UI, 표준 양식 입력 편의(드롭다운·자동완성).
- **개인정보/보안**: 최소 수집 원칙, 첨부파일 접근 권한 통제.
- **호환성**: 군청 표준 브라우저 환경 지원, 가능 시 모바일 열람 고려(향후).

## 8. 기술 스택 / 아키텍처 추천 (근거 포함)

> 전제: **사용자 약 20명, 내부망 중심, 소규모 운영**. 운영·유지보수 부담 최소화와
> 표준 기술 활용을 우선한다. 아래는 추천안이며 군청 표준·보안 정책에 맞춰 확정한다.

### 8.1 추천 아키텍처 — 웹 기반 3-Tier
| 계층 | 추천 | 근거 / 대안 |
|------|------|-------------|
| 프론트엔드 | React (SPA) + 컴포넌트 UI 라이브러리 | 대시보드·표 입력 화면 구현 생산성 높음 / 대안: Vue |
| 백엔드 | 검증된 웹 프레임워크(예: Spring Boot 또는 Django/Node) | 인력·유지보수 용이성 기준 택일 / RBAC·파일 업로드 표준 지원 |
| 데이터베이스 | PostgreSQL(또는 MySQL) RDB | 사업비 집계·관계형 분석에 적합, 안정적 |
| 파일 스토리지 | 서버 파일시스템 또는 사내 오브젝트 스토리지 | 이미지(위치도·현장사진) 저장, 백업 연계 |
| 배포 | 단일 사내 서버(필요 시 컨테이너) | 소규모 트래픽, 내부망 운영에 충분 |

### 8.2 핵심 구현 방향
- **인증/권한**: 로그인 + 역할 기반 접근통제(관리자/중간관리자/일반). 부서·서무 속성 반영.
- **회차/분기 스냅샷**: 보고회(2·7·11월)·순기표(1·4·7·10월)별 데이터를 버전으로 보존해
  변경 추적을 데이터 모델 수준에서 보장.
- **공통코드 기반 분류**: 유형·분야·부서·읍면을 코드 테이블로 관리해 확장성 확보.
- **백업·유지보수**: 정기 백업과 단순한 운영 구조로 군청 자체 운영 부담 최소화.

### 8.3 검토 트레이드오프
- 자체 구축(맞춤 기능, 초기 개발 필요) vs 상용 협업툴 조합(빠르나 보고회/순기표 특수 양식·변경
  추적 구현 한계). → 본 시스템은 **보고회·순기표 특화 요구**가 크므로 자체 구축형 권장.

## 9. 단계별 개발 로드맵
| 단계 | 산출물 | 비고 |
|------|--------|------|
| 1. 기반 | 로그인·권한(3단계)·부서/팀·공통코드·사용자 관리 | 모든 기능의 토대 |
| 2. 정책 | 정책 아카이브(시행/구상)+유형·분야 분류+검색, 의견·사업제안 | 협업 핵심 |
| 3. 주요업무 | 주요업무 보고회 입력 양식(12항목+참고자료)+회차(2·7·11월) 비교 | 보고 디지털화 |
| 4. 순기표 | 순기표(전 사업)+정책적 주요사업 체크+부서/읍면/종료연도 별도 관리 | 분기 운영 |
| 5. 대시보드 | 유형별·읍면별 사업비 등 지표 시각화·필터 | 의사결정 지원 |

> 연간 일정 연계: 보고회(2·7·11월), 순기표(1·4·7·10월) 일정에 맞춰 단계 3~4를
> 우선 가동할 수 있도록 배치한다.
